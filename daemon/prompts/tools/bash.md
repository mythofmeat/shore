Run a Bash command on the daemon host. Use this for reading, writing, editing, listing, searching, moving and deleting files; Git; fetching URLs with curl; calculations; and other command-line work. Commands run in your workspace by default. Set workdir to a directory (relative to your workspace or absolute) when needed. Each call starts a fresh, non-interactive Bash shell with pipefail enabled; cd and exported variables do not persist between calls. Files do persist. Standard input is closed; use pipes or heredocs for input. Run commands in the foreground and wait for them to finish.

Use familiar commands such as cat, sed, rg, find, mkdir, mv, rm, git, curl, jq and python3. Read files before editing them and quote paths and text carefully. Use a quoted heredoc when writing literal multiline text. Join dependent steps with && so a failed step stops the next one. Use `search` for semantic workspace search and `search_chat_logs` for conversation retrieval.

For Git, inspect status and diffs, stage the intended paths, and create ordinary commits; commits use your character identity. Preserve existing history: do not force-push, amend or rebase existing commits, delete history, or discard uncommitted work. Correct mistakes with new edits and commits. These are instructions for using the shell; remote branch protection is what enforces push restrictions.

The result includes the exit status, stdout and stderr. Check these before claiming success. Output is bounded; narrow large results with paths, patterns, head, tail or sed, or redirect output to a file and read it in parts. Shore's configured tool timeout applies and cancellation stops the command's process group. Changes made before an error or timeout remain on disk; inspect the result before retrying a command that changes things. Changes to SOUL.md, USER.md, AGENTS.md, TOOLS.md and MEMORY.md are queued for prompt reload.

This is unrestricted command execution as the daemon user. The working directory is a convenience, not a sandbox: commands can access the daemon's environment, network and any files its user can access. In Docker, the container and its mounts define that access.
