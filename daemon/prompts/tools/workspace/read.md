Read a file, or list a folder, on the daemon host. Relative paths resolve from the workspace; absolute paths are accepted. Access is limited by the OS permissions of the user your tools run as, as with Bash.

`file_path` can also be a `[[link]]` copied from a Markdown file, like `[[harbor-district]]` or `[[city/locations/market]]`. `[[name]]` finds any file anywhere in the workspace by its name, with or without the extension: `[[notes]]` or `[[notes.md]]`, `[[2025-log]]` or `[[2025-log.csv]]`, `[[photo.jpg]]`. Names match exactly, including case. When several files have the name, folders in front of it or its extension pick one, as in `[[city/market]]` or `[[photo.png]]`. Folders in a link must be the ones directly above the file, and a leading `/` anchors them at the workspace root, as in `[[/market]]`. Among several, a file with exactly that name beats one that matches without its extension, and a text file beats a binary one, so `[[photo]]` opens `photo.md` even when there is a `photo.png`. `[[name/]]` with a trailing `/` finds a folder the same way; when it has an `INDEX.md`, that is what is read, followed by the folder's listing, or by how to list it when the listing doesn't fit. `![[name]]` finds a file the same way as `[[name]]`. Text from `|` or `#` on is ignored. Hidden notes and notes in hidden folders have no name; read those by path. A plain path is still read as a path. Only when nothing exists there is it tried as a name, a file's and then a folder's, and the result says it was found by name. A folder path is also tried as a file name first, unless it ends in `/`; when no name fits, the folder is listed. If more than one file still fits, the read fails and lists a link that picks each one; if none fits, it suggests the closest names. The result starts with the file's real path, which is what `edit` takes.

A folder is listed like `tree`: everything below it, folders marked with `/`, hidden entries left out and counted. Long listings are cut off; read a subfolder for the rest.

UTF-8 text is returned with one-based line numbers. A page contains at most 2000 lines, with at most 2000 characters per line, and is bounded by the configured result limit. Partial views identify omitted content and the next line offset. Empty files and offsets beyond EOF are reported explicitly.

Markdown files also expand unique local image references fully visible in the returned page, while preserving the numbered source. Image paths resolve relative to the Markdown file. Inline and reference-style Markdown images are supported, as are wikilink embeds such as `![[name.png]]`, `![[name]]` or `![[folder/name.png|alt text]]`, which find a file the way `file_path` links do and show it only when it is a PNG, JPEG, WebP, or GIF picture: `![[photo]]` finds `photo.md` while there is one, and `![[photo.png]]` shows. An embed that finds any other file or a folder, matches no file, or matches more than one is reported, with the picture of the same name, the close pictures or the matching files as links to paste, and not read. Code examples and remote URLs are ignored. Expansion requires a Markdown file no larger than 1 MiB. Missing, unsupported, or oversized images, and images that cannot fit the inline image budget even after reduction, are reported without failing the text read and are not read.

PNG, JPEG, WebP, and GIF files up to 64 MiB are returned as actual image input, as a copy reduced to the configured size and format; GIFs use the first frame. The file itself is never changed. Unless the configuration turns them off, a reduced image comes with a note of its original and sent size, format, and token cost, and `original: true` sends an image file at the full resolution the model accepts instead. Each result sends at most 20 images, within the configured byte budget for reduced image data (5 MiB by default); images considered in order that do not fit are listed as not sent without failing the read, and later smaller images can still be sent. Image delivery requires a supported model and endpoint; failures are reported explicitly. Offset and limit apply only to text. Special files, unsupported binary formats, and invalid UTF-8 are rejected.
