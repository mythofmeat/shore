Read a file on the daemon host. Relative paths resolve from the workspace; absolute paths are accepted. Access is limited by the daemon user's OS permissions, as with Bash.

`file_path` can also be a `[[link]]` copied from a Markdown file, like `[[harbor-district]]` or `[[city/locations/market]]`. `[[name]]` finds the note `name.md` anywhere in the workspace, and `![[name.png]]` or `![[name]]` finds a PNG, JPEG, WebP, or GIF picture by its file name, or the note when no picture has that name. Names match exactly, including case. Folders in a link must be the ones directly above the file, and a leading `/` anchors it at the workspace root, as in `[[/market]]`. Text from `|` or `#` on is ignored. Hidden notes, notes in hidden folders, and all-caps notes such as `README.md` have no name; read those by path. A plain path is still read as a path. Only when nothing exists there, or it is a folder, is it tried as a name: a picture if it ends in a picture extension, a note otherwise, and the result says it was found by name. If more than one file fits, the read fails and lists a link that picks each one; if none fits, it suggests the closest names. The result starts with the file's real path, which is what `edit` takes.

UTF-8 text is returned with one-based line numbers. A page contains at most 2000 lines, with at most 2000 characters per line, and is bounded by the configured result limit. Partial views identify omitted content and the next line offset. Empty files and offsets beyond EOF are reported explicitly.

Markdown files also expand unique local image references fully visible in the returned page, while preserving the numbered source. Image paths resolve relative to the Markdown file. Inline and reference-style Markdown images are supported, as are wikilink embeds such as `![[name.png]]`, `![[name]]` or `![[folder/name.png|alt text]]`, which find a picture by name the way `file_path` links do. An embed that names a note is left as text; one that matches no picture or note, or more than one picture, is reported, with the close or matching pictures as links to paste, and not read. Code examples and remote URLs are ignored. Expansion requires a Markdown file no larger than 1 MiB. Missing, unsupported, or oversized images, and images that cannot fit the inline image budget even after reduction, are reported without failing the text read and are not read.

PNG, JPEG, WebP, and GIF files up to 64 MiB are returned as actual image input, as a copy reduced to the configured size and format; GIFs use the first frame. The file itself is never changed. Unless the configuration turns them off, a reduced image comes with a note of its original and sent size, format, and token cost, and `original: true` sends an image file at the full resolution the model accepts instead. Each result sends at most 20 images, within the configured byte budget for reduced image data (5 MiB by default); images considered in order that do not fit are listed as not sent without failing the read, and later smaller images can still be sent. Image delivery requires a supported model and endpoint; failures are reported explicitly. Offset and limit apply only to text. Directories, special files, unsupported binary formats, and invalid UTF-8 are rejected.
