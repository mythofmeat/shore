Search this character’s archived conversation history across all threads, including retired threads. Use `query` for keyword search, `start_time` and/or `end_time` for an inclusive RFC3339 time range, `model` to restrict to assistant messages generated by a matching model, or combine them. Three matching messages are returned by default, up to 50 with `max_results`. A notice identifies additional matches; narrow the search or increase the limit to see more.

Results are readable transcript blocks. Each message has a timestamp, role, model when known, message ID, and segment:ordinal location within the named thread. Matching messages are marked; their immediately preceding and following visible messages provide context. Overlapping context is merged and displayed in conversation order within each block. Complete visible text, paragraphs, and formatting are preserved.

Messages copied into other threads by a fork are one event, returned once as a search hit, with other archive locations listed. Separate events with identical text stay separate. Context comes from the hit’s representative thread, including across segment boundaries. Deduplication happens before the result limit.

Active messages are not searched: they become searchable after compaction, clearing, or thread retirement archives them. Only visible chat text is searched and returned; private thinking, tool payloads, and regenerated alternatives that were never sent are excluded.

The header shows the archive’s oldest and newest timestamps and the current time. Check these before interpreting an empty result: a range after the newest archive entry may still be in your active context, and one before the oldest entry predates the archive. Response timestamps and echoed time bounds use the named time zone with explicit UTC offsets; your input bounds are interpreted as written.

Search can blend lexical and semantic matches when embeddings are configured. Pending semantic indexing and embedding failures are reported; lexical matching remains available during backfill. `mode: "vector"` searches only currently embedded content. Unknown models on old messages and user turns are excluded by the `model` filter, so an empty filtered result can mean “not attributable.” Use `model_history` to see which models served you over a period.
