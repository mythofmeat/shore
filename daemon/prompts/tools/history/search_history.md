Search this character’s archived visible chat text across all threads, including retired threads. Active messages are not searched until compaction, clearing, or thread retirement archives them. Private thinking, tool payloads, and regenerated alternatives that were never sent are excluded.

Filter by `query`, an inclusive `start_time`/`end_time` range, and `model`, alone or combined. Provide at least one of `query`, `start_time`, `end_time`, or `model`. Text matching can include semantic matches when embeddings are configured; pending semantic indexing and embedding failures are reported in the result.

A query returns close matches only: messages that contain the query as a phrase or contain all of its distinctive words, or whose semantic similarity reaches the embedding model's minimum. When nothing is close, the result says so and gives the best similarity it found, instead of returning the nearest unrelated messages. Two or three distinctive words search best; a long query with several phrasings at once matches less well. To read what was said around a moment, give a time range without a query.

Results are transcript blocks. Each message shows a timestamp, role, model when known, message ID, and segment:ordinal location within a named thread. Matching messages are marked, with their semantic similarity when known, and with the immediately preceding and following visible messages as context; overlapping context is merged. Messages copied into other threads by a fork are one event, returned once with the other archive locations listed; separate events with identical text stay separate. Deduplication happens before `max_results` is applied, and a notice identifies additional matches.

The header shows the archive’s oldest and newest timestamps and the current time. Check it before interpreting an empty result: a range after the newest entry may still be in active context, and one before the oldest predates the archive. Timestamps use the named time zone with explicit UTC offsets.
