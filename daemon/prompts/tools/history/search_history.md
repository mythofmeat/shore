Search your own conversation history, including compacted older messages and the active conversation window. Use this when the user asks what you discussed before, when you need to verify a past exchange, when you need messages from a specific time range, or when the answer may be in the transcript rather than in curated memory files. Provide `query` for keyword search, `start_time` and/or `end_time` for an inclusive RFC3339 time range, `model` to restrict to assistant messages minted by a matching model, or combine them.

Only visible chat text is searched — private thinking and tool-call/tool-result payloads are never indexed, matched, or returned. Search uses a rebuildable FTS cache and, when an embedding provider is configured, can blend lexical and semantic candidates. Semantic indexing fills incrementally, so diagnostics report indexed, total, and pending chunks; lexical matching remains complete while that backfill is unfinished. An embedding failure falls back to lexical search and is reported.

Results contain the complete visible text of each matching message, preserving paragraphs and formatting. Each hit also includes the immediately preceding and following visible messages, including across archived/active boundaries. Three matching messages are returned by default. Unselected regenerated answers are omitted unless `include_alternatives` is true.

Each result's `model` field is the model that generated that message (regenerated alternatives carry their own). It is `null` on user turns and on messages stored before model tracking, and the `model` filter skips those — so an empty result for an old period means "not attributable", not "never said". To audit how you sounded on one model versus another, combine `model` with a time range and compare messages from each. The `model_history` tool tells you which models served you over a period.
