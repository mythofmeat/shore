Search your archived conversation history — everything that compaction has already swept out of your active context. Use this when the user asks what you discussed before, when you need to verify a past exchange, when you need messages from a specific time range, or when the answer may be in the transcript rather than in curated memory files. Provide `query` for keyword search, `start_time` and/or `end_time` for an inclusive RFC3339 time range, `model` to restrict to assistant messages minted by a matching model, or combine them.

The active conversation is not searched, and there is no way to ask for it. Everything you can still see in this context window is excluded by construction, so a search only ever tells you something you had forgotten. When you want a message that is still in front of you, read it rather than searching for it. A message becomes searchable when compaction archives it, which is also the moment it leaves your context.

Only the answer you actually gave is stored. Regenerated alternatives you did not end up sending are never indexed and cannot be returned, so every hit is something that really was said in the conversation.

Only visible chat text is searched — private thinking and tool-call/tool-result payloads are never indexed, matched, or returned. Search uses a rebuildable FTS cache and, when an embedding provider is configured, can blend lexical and semantic candidates. Semantic indexing fills incrementally, so diagnostics report indexed, total, and pending chunks; lexical matching remains complete while that backfill is unfinished. An embedding failure falls back to lexical search and is reported.

Every timestamp in the response — each result, the neighbours, `archive_boundary`, `now`, and the echoed `time_range` — is rendered in one zone, named by `time_zone`, with an explicit UTC offset. That is true no matter how the message was stored: the archive spans several eras with different encodings, and they are all converted for you, so timestamps in a response are directly comparable to each other and to the `[wall clock]` markers you see in conversation. Your `start_time`/`end_time` bounds are read as written — if you pass a `Z` bound it means UTC — and the echoed `time_range` shows them converted, so you can confirm you asked for the window you meant.

`archive_boundary` gives the oldest and newest timestamps in the archive, and `now` gives the current time. Use them to read an empty result correctly: a window after `archive_boundary.newest` has not been archived yet and may still be in your context, one before `archive_boundary.oldest` predates the archive, and one inside the boundary genuinely holds no messages. Without checking, an empty result is ambiguous and you should not treat it as proof that nothing was said.

Results contain the complete visible text of each matching message, preserving paragraphs and formatting. Each hit also includes the immediately preceding and following visible messages, including across segment boundaries. Three matching messages are returned by default.

Each result's `model` field is the model that generated that message. It is `null` on user turns and on messages stored before model tracking, and the `model` filter skips those — so an empty result for an old period means "not attributable", not "never said". To audit how you sounded on one model versus another, combine `model` with a time range and compare messages from each. The `model_history` tool tells you which models served you over a period.
