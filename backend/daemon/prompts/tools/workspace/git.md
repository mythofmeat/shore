Run a git command in your workspace, which is a git repository. Pass the subcommand on its own (`"commit"`) and each argument as a separate element of `args` (`["-m", "why this matters"]`) — the command is not parsed as a shell line, so quoting, pipes, and redirects have no meaning here. Use it to keep a history of your memory: `status` and `diff` to see what you've changed, `add` then `commit` to record it, `log` to look back at what past-you saved and why. Commits are attributed to you, separately from anyone else working in the same repository. History is append-only: anything that discards, rewrites, or forces is refused — `reset --hard`, `rebase`, `restore`, `clean -f`, forced checkouts, history deletion, and checking a path back out over your working copy (`checkout HEAD -- <path>`, which would throw away edits you have not committed). `config` is refused too, as is anything that reaches a remote — `push`, `fetch`, `pull`, `clone`, and remote changes: syncing is the daemon's job, not yours.
